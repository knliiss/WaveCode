# WaveCode V1 — Binary and Optical Wire Format

This file fixes the meaning of an existing V1 codeword. Changing the bit order, identity ranking,
CRC, whitening, Reed–Solomon parameters, or optical symbol levels requires a new format version.

## Domain

A code represents one track reference and either no timestamp or a timestamp in
the inclusive range 0–65535 seconds.

Platforms currently supported:

- YouTube Music: exactly 11 characters from `ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789-_`.
- Spotify: exactly 22 characters from `0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz`.
- Apple Music: unsigned 64-bit song ID and two lowercase ASCII storefront letters.

Only the track ID, Apple Music storefront (when applicable), and optional timestamp are stored.
Unrelated URL parameters and track names are not stored. This is not a cryptographic signature.

## Identity ranking

All platforms occupy disjoint integer ranges. The ranking is *not* a hash:

```
Y = 64^11
A = 676 * 2^64
S = 62^22

rank(YouTube ID) = base64_decode(ID)
rank(Apple ID, storefront) = Y + song_id + storefront_index * 2^64
rank(Spotify ID) = Y + A + base62_decode(ID)

storefront_index = 26 * (first_letter - 'a') + (second_letter - 'a')
total_capacity = Y + A + S
```

The most significant digit is on the left. The rank is stored in 131 bits.
All ranks outside `[0, total_capacity)` must be rejected.

## Message layout (168 bits, 21 bytes)

| Bits, most significant first | Meaning |
| --- | --- |
| 0–2 | Version: unsigned 3-bit integer, equal to 1 |
| 3–4 | Mode: 0 = track only, 1 = track and timestamp |
| 5–135 | Identity rank, unsigned 131-bit big-endian integer |
| 136–151 | Timestamp, unsigned 16-bit big-endian seconds |
| 152–167 | CRC-16/CCITT-FALSE of the first 19 bytes |

If mode is 0, the timestamp bytes must be zero. If mode is 1, the timestamp may be
zero. Modes 2 and 3 and versions other than 1 must be rejected.

CRC parameters: polynomial 0x1021, initialization 0xFFFF, no reflection, final XOR
0x0000. The ASCII test vector `123456789` has CRC `0x29B1`.

The 21 bytes are split into 28 consecutive six-bit symbols, most significant bit
first in both bytes and symbols.

## Whitening

Whitening is a reversible XOR mask; it provides neither authentication nor encryption.

For each of the 28 six-bit symbols, starting from mask `0x25`:

```text
overflow = (mask & 0x20) != 0
mask = (mask << 1) & 0x3F
if overflow:
    mask ^= 0x03
symbol ^= mask
```

The same operation is used to undo whitening.

## Reed–Solomon

The 28 whitened symbols are encoded as a systematic `RS(34,28)` code over
`GF(2^6)` defined by the irreducible polynomial `x^6 + x + 1` (`0x43`).

The primitive field element is `α = 2`. The six parity symbols are appended
after the 28 data symbols. The generator polynomial has roots
`α^0, α^1, α^2, α^3, α^4, α^5`.

A decoder may correct combinations of `e` unknown symbol errors and `s` known
erasures satisfying `2e + s <= 6`; after correction it must still validate
CRC, version, mode, rank, and timestamp representation. Correction is not guaranteed
outside that bound.

Every codeword is exactly **34 six-bit symbols**, regardless of platform or timestamp.

## Optical levels

The frame contains **36 pairs of upper and lower rails**, in this order:

```text
START | 34 codeword symbols | END
```

- Each data symbol `b` has upper level `b >> 3` and lower level `b & 7`.
- Each data rail level is in 0–7.
- The START marker has upper/lower levels (9,2).
- The END marker has upper/lower levels (2,10).
- All rail lengths have form `base_height + level * height_step`, with strictly
  positive `base_height` and `height_step`.
- Upper rails extend upward from the top edge of a central clear gap; lower
  rails extend downward from its bottom edge.
- Rotating a code by 180° reverses the 36 columns and exchanges upper/lower rails.

The SVG canvas width and height, lateral pitch, rail width, central gap, margin,
corner radius and physical dimensions are **rendering parameters**, not fixed
numeric values in the wire format. Readers must infer the geometric scale.
Not every theoretical rendering size will be optically readable.

A decodable raster must be independently verified through the RS codeword and CRC.
A correctly parsed SVG is not evidence of reliable camera recognition.

## Backward compatibility

The 21–23-symbol legacy format is distinct from V1. Readers must not silently
reinterpret a legacy codeword as V1 or vice versa.
